# Голосовой ввод мастера и исполнителя

Обе формы используют один обработчик `transcribeVoice`: мастер добавляет
описание при создании наряда, исполнитель — выполненные работы при завершении.
Распознанный текст дополняет введённый вручную и остаётся доступным для правки.

По предоставленной документации запрос — `POST /api/ai/transcribe`,
multipart-поле `audio`, ответ — `{"text":"Распознанная речь"}`.
Приложение отправляет WAV PCM16, моно, 16 кГц, с текущим Bearer-токеном.
Размер файла ограничен 25 МБ. Запрос распознавания не создаёт и не закрывает наряд.

## Разбор ответа HTTP 200

Раньше приложение принимало только строковое поле `text` в корне JSON.
Обработчик также поддерживает следующие варианты:

| Формат | Пример |
|---|---|
| Обычный текст или JSON-строка | `Распознанная речь` или `"Распознанная речь"` |
| Поле результата | `{"transcript":"…"}`, `{"transcription":"…"}` |
| Вложенный результат | `{"data":{"text":"…"}}`, `{"result":{"text":"…"}}` |
| Объект транскрипции | `{"transcription":{"text":"…"}}` |
| Сегменты с текстом | `{"segments":[{"text":"Первая фраза."},{"text":"Вторая фраза."}]}` |

Поддерживаются вложенные `data`/`result`, JSON с BOM и JSON, закодированный
в строку. Глубина разбора ограничена. Для списка сегментов каждый элемент
должен содержать строковый `text`; неполный список отклоняется целиком.

Корректный JSON с результатом принимается даже при ошибочном
`Content-Type: text/html`. Сообщение «HTML вместо текста» определяется
по разметке в содержимом ответа, а не только по заголовку. Произвольный
текст с HTML-заголовком не используется как результат распознавания.

Автоматические перенаправления голосового запроса отключены: HTTP 303
может превратить POST в GET и потерять аудио. Ответы 301/302/303/307/308
теперь показывают отдельную ошибку перенаправления с исходным HTTP-статусом.
Аудио повторно не отправляется на другой адрес.

Поля `message`, произвольные поля JSON и объекты с явным признаком ошибки
не используются как описание работы. HTML и пустое тело HTTP-ответа вызывают
отдельные сообщения об ошибке, переведённые на русский и казахский.
Пустая распознанная строка означает, что речь не распознана.
Ручной текст сохраняется при любом из этих отказов.

## Локальная диагностика

При неверном ответе в журнале появляется строка, например:

```text
Voice transcription response: POST https://hackaton.fenixkst.kz/api/ai/transcribe, HTTP 200, content-type text/html, shape html(length=1200)
```

В этой строке записываются адрес endpoint без query-параметров, HTTP-статус, тип содержимого и структура
известных полей. Значения ответа, аудио, неизвестные имена полей и токен
авторизации не выводятся.

HTTP 200 с HTML, пустым телом или неизвестным форматом не подтверждает
успешное распознавание. В таком случае серверу нужно возвращать документированный
результат или корректную HTTP-ошибку; приложение не может извлечь речь из
пустого ответа или страницы сайта.

Исправление проверено локально на подставных ответах API: форматах результата,
ошибках, формах обеих ролей, редактировании и сохранении черновика исполнителя.
Реальные запросы на сервер по просьбе пользователя не выполнялись.
Дополнительно проверены реальные multipart-запросы и ответы HTTP-сервера
на `127.0.0.1`: WAV с Bearer-токеном, корректный JSON с HTML-заголовком,
настоящая HTML-страница и перенаправление 303. Это не проверяет работу Whisper.
Фактическое тело проблемного ответа на Android и наличие перенаправления
на действующем сервере пока не установлены.

## Что передать разработчику бэкенда, если ошибка повторится

```text
Голосовой ввод не возвращает результат для мобильных ролей MASTER и EXECUTOR.
POST https://hackaton.fenixkst.kz/api/ai/transcribe
Authorization: Bearer <текущий токен пользователя>
Content-Type: multipart/form-data; boundary=<граница multipart>
Файл: поле audio, description.wav, audio/wav, PCM16, 16 кГц, моно.
Ожидается: HTTP 200 с JSON {"text":"Распознанная речь"}.
Для отказов по контракту: 422 при отсутствии речи, 502 при сбое Whisper.
```

Приложите безопасную строку `Voice transcription response` или
`Voice transcription redirect` из новой сборки. При настоящем HTML или
перенаправлении нужно проверить маршрут POST, правила прокси и ответ Whisper:
API должен возвращать результат или HTTP-ошибку, а не страницу сайта.
