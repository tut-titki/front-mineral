# Проверка мастера смены по документации НарядAI

Дата: 8 октября 2026 года. Источник: приложенная пользователем документация
«НарядAI — документация для фронтенда», разделы 2–6 и 8–17, 19–21.

Проверены существующие экраны и клиентские запросы роли MASTER. Проверка кода
и тестов с контролируемыми ответами API не подтверждает работу всех функций
на действующем сервере или конкретном телефоне.

| Функция | Результат сверки |
|---|---|
| Вход, восстановление сессии, язык профиля, смена пароля и выход | Телефон/пароль, `/auth/me`, защищённое хранилище, обработка 429 и отвязка push соответствуют контракту. Исправлен выход при 401 запросов общего API-клиента мастера. |
| Роль MASTER | Защищённый маршрут мастера доступен только MASTER; MANAGER и ADMIN не проходят мобильный вход, согласно разделению мобильных и веб-ролей. |
| Список нарядов | Использует компактный список, фильтры статуса/приоритета/участка/оборудования/исполнителя/бригады/просрочки и постраничную загрузку. Отдельный фильтр `type` в интерфейсе отсутствует. |
| Канбан | Колонки и счётчики берутся из `/work-orders/board`; обновления ограничены по частоте. Перетаскивание использует действия сервера. |
| Создание | Обязательны описание, участок, оборудование, исполнитель или бригада, срок или норматив. Бригада без явного исполнителя поддерживается. Повторная отправка автоматически не производится. |
| Рекомендации | Передаются оборудование, описание и шифр. Подсказка шифра/норматива применяется явной кнопкой. |
| Изменение и переназначение | Правка ограничена активными статусами. Переназначение REJECTED разрешено, COMPLETED/AI_REVIEW/CLOSED/CANCELLED запрещено. |
| Отмена | Исправлена: доступна во всех шести активных статусах, включая IN_PROGRESS и REWORK. |
| Закрытие и доработка | CLOSE и SEND_TO_REWORK доступны в AI_REVIEW. Оценка мастера 1–5, комментарий и фактический простой передаются серверу. |
| Завершение работ мастером | Форма COMPLETE проверяет текст, шифр и фото для аварийного типа, отправляет числовые количества. Таймаут ожидания AI установлен в 250 секунд. |
| Конфликты действий | Исправлено: после 409 карточка перечитывается, чтобы убрать устаревшие действия. |
| Диалоги причины и комментария | Исправлено освобождение контроллера текста: оно выполняется после завершения анимации закрытия диалога. |
| Фото | Поле `file`, лимит 15 МБ и до пяти фото, подписанные ссылки сохраняются. При 401 картинки обновляется наряд. Добавлен `takenAt` в UTC при наличии времени файла, включая форму завершения мастером. |
| Голос | Поле `audio`, WAV до 25 МБ, ответ `{text}`, результат остаётся редактируемым. Общий обработчик мастера и исполнителя также принимает текст и вложенный JSON, отдельно сообщает о HTML и пустом ответе. [Форматы и локальная диагностика](voice_input.md). Работа Whisper на действующем сервере не подтверждена. |
| AI-проверка | Отображаются вердикт, оценки, объяснение, сильные стороны, улучшения и предупреждение needsMasterReview. |
| Отчёт наряда | JSON `/reports/work-order/:id` и PDF `/reports/work-order/:id.pdf` соответствуют документации. |
| Отчёты и выгрузки | Используются общие фильтры периода, ISO from/to, участка, оборудования, исполнителя и бригады. Для рейтинга бригад выгрузка передаёт `report=brigades`; для материалов — `groupBy`. |
| Аналитика | Дашборд, прогноз и список аномалий подключены. `topAreas` не отображается; ручной запуск `/analytics/anomalies/run` не реализован. |
| AI-помощник | Текст ответа и история поддерживаются. Исправлен разбор `intent.intent` из объекта. Дополнительные интерактивные карточки из `data` не реализованы; документация описывает их как необязательные. |
| Realtime | Авторизация токеном, обновление по обоим событиям и повторная загрузка после reconnect. Добавлена обработка connect_error unauthorized с завершением текущей сессии. |
| Уведомления и FCM | Регистрация после входа, отвязка до выхода, аварийный канал emergency_orders, открытие наряда по workOrderId и подтверждаемое переназначение suggestedExecutorId. Доставка FCM на телефоне требует отдельной проверки. |
| История оборудования | Подключена; поддерживается документированный ответ 200 null. |
| QR | Сканер, чтение `/equipment/qr/:token` и печать QR отсутствуют. |
| Офлайн мастера | Постоянная офлайн-очередь действий MASTER не реализована. clientActionId используется для повторов действий в открытом экране. Создание и загрузки не повторяются автоматически. |
| Ошибки полей 400 | Локальная валидация формы есть. Ошибки `details` при входе разбираются; форма создания пока показывает серверную ошибку общим сообщением без отдельной подсветки всех полей из details. |

## Проверки

- Финальный полный `flutter test`: все 211 тестов прошли.
- `flutter analyze`: ошибок и предупреждений анализатора нет.
- `git diff --check`: ошибок нет.
- `flutter build apk --debug --no-pub`: сборка успешна,
  файл `build/app/outputs/flutter-apk/app-debug.apk`.
- Дополнительные сценарии: все методы защищённого API при 401, устаревший
  ответ от старого JWT, отказ входа и 400 без выхода, объект intent,
  загрузка фото с UTC takenAt, выход мастера и обновление карточки при 409.
- `/health`: HTTP 200, `status=ok`.
- `/health/ready`: HTTP 200, `database=true`, `ollama=true`.

Health-проверки не проверяют Whisper и FCM. Авторизованные действия с реальными
нарядами, файлами и сотрудниками на сервере в этом аудите не выполнялись.
Проверка записи на физическом Android-устройстве не выполнена: подключённого
доступного Android-устройства нет.
