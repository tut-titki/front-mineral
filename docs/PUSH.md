# Push исполнителя

Клиент регистрирует FCM-токен после входа и восстановления сессии:
`POST /api/devices {"token":"…","platform":"android"}`.
При обновлении токена отвязывает старый. При выходе выполняет
`DELETE /api/devices/<token>` перед удалением JWT.

## Подключение Firebase для Android

1. В Firebase-проекте команды зарегистрировать Android-приложение
   с package name `com.example.mineral`.
2. Поместить его `google-services.json` в `android/app/google-services.json`.
   Gradle подключит конфигурацию автоматически.
3. Backend должен использовать Firebase Admin credentials того же проекта.
   Серверный ключ нельзя помещать в приложение или репозиторий.
4. Пересобрать и установить приложение, войти и разрешить уведомления.

Без конфигурации приложение продолжает работать с API/Socket.IO,
но FCM не запускается. Демо-режим FCM не использует.

## Каналы и открытие наряда

`NEW_ORDER` + `EMERGENCY`: Android-канал `emergency_orders`,
максимальная важность, отдельный звуковой сигнал и вибрация.
Остальные: `orders`. Громкость регулируется настройками телефона.
Сервер должен передавать соответствующий `android.notification.channelId`,
чтобы ОС выбрала нужный канал в фоне.

Категории iOS в клиенте: `EMERGENCY_ORDER` и `ORDER`.
Для iOS отдельно нужны iOS-проект, `GoogleService-Info.plist`, APNs key,
Push Notifications capability и Background Modes / Remote notifications.

При открытом приложении показывается локальное уведомление с готовыми
`notification.title/body`. В фоне уведомление отображает ОС без дубля.
Тап использует `data.workOrderId`, загружает наряд и проверяет владельца.
Если сессии нет, открытие откладывается до входа исполнителя.

## Проверка на телефоне

- Новый обычный и аварийный наряд: открытое, свёрнутое и закрытое приложение.
- Тап открывает нужную карточку; чужой/удалённый наряд не открывается.
- Повторный вход/обновление токена перепривязывает устройство.
- Выход удаляет регистрацию устройства до удаления локального JWT.
