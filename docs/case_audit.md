# Сверка с кейсом «Костанайские минералы»

Проверено 5 октября 2026 года по PDF «Кейс №1 Костанайские минералы рус.pdf» и текущему коду.
Анализатор: без ошибок. Все 46 тестов прошли. Проверка на физических телефонах,
в рабочих перчатках, push в фоне и скорости загрузки по мобильной сети не проводилась.

Проект сейчас — работающий локальный прототип на моках. Изменения в одном DemoStore
сразу видны обеим ролям внутри одного запуска, но между телефонами обмена нет.
Наличие экрана или модели не означает готовность соответствующего серверного сервиса.

## Что можно закончить до backend

1. Порядок очереди исполнителя на моках.
2. Недостающие фильтры мастера.
3. Крупные элементы изменения количества материалов.
4. История оборудования и справочник нормативов.
5. Долговечные черновики, включая фото. Очередь сетевых команд — отдельная задача.
6. Согласовать DTO, ID справочников и единицы, статусы, ошибки, фотографии и версионирование.
   Исполнитель зависит от ExecutorRepository, но мастер по-прежнему напрямую зависит
   от DemoStore: одного переключателя недостаточно для подключения всей системы.
7. Полный мок-сценарий проверки → доработки → повторной отправки → приёмки,
   с явно демонстрационными результатами, без выдачи их за работающий ИИ.

## Интеграция, обязательная для MVP

Авторизация по ролям; постоянное хранение; API обеих ролей; межустройственная синхронизация;
push; фоновый контроль сроков и эскалации; ИИ-проверка с базовой проверкой фото;
отчёты и расчёт рейтинга. Моки сохраняем для демо и тестов, реальные данные компании
для разработки не требуются.

## Желательно и бонус

- Офлайн-действия; повторные напоминания; подбор исполнителя; аналитика поломок;
  полноценное мультимодальное сравнение фото; отчёты по материалам/простоям;
  PDF/Excel; панель руководителя — не смешивать с выполненным MVP.
- Голосовой ввод и ассистент, прогноз отказов, QR — бонусы. Текстовый ввод
  работ уже покрывает обязательную форму: отсутствие голоса не блокирует MVP.
- Казахская локализация реализована.
- Для защиты ещё нужны APK/PWA, доступная панель и тестовые аккаунты, тестовые данные,
  презентация до десяти слайдов и резервное демо-видео. Сквозной сценарий на двух-трёх
  телефонах без backend сейчас показать нельзя.

## Обновление после сверки: доработан исполнитель

- Реализованы порядок очереди и номера позиций; блокируется одновременный запуск
  второго наряда. Текущая работа выше остальных, приостановленные — сразу за ней.
- Кнопки количества материалов 60×60; точное значение вводится через bottom sheet.
  Штучные материалы принимают только целые количества; удаление подтверждается.
- Черновики и фото на нативных платформах сохраняются в файлах и восстанавливаются
  после перезапуска; ошибки чтения/записи имеют повтор. Веб остаётся демо в памяти.
- Карточка результата разделена на проверку и отчёт; доработка выделена; основное
  действие закреплено снизу. Просрочка явно показана в списке.
- Повторные нажатия блокируются во время изменения статуса/отправки/выбора фото.
- Все новые подписи добавлены в RU/KK.

Таблица выше фиксирует состояние на момент первоначальной сверки. Очередь, кнопки
количества и постоянные черновики из списка «до backend» теперь реализованы.
Backend существует по сообщению пользователя; его API ещё не изучен, документация
