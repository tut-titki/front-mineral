# Вход и сессия

Основание: docs/FRONTEND.md backend, разделы 1–4 и 12.
Адрес: https://hackaton.fenixkst.kz.

- POST /api/auth/login: phone и password. Вход принимает любой непустой пароль, без ограничения длины.
  Маска +7 для местных номеров, международные номера с + сохраняются без подмены.
- После входа GET /api/auth/me загружает профиль и язык ru/kk.
- EXECUTOR открывает мобильный экран исполнителя с реальным ID, MASTER — экран мастера.
  MANAGER/ADMIN относятся к веб-панели и не открываются в мобильном режиме.
- JWT хранится через flutter_secure_storage на нативных платформах. В вебе — только
  в памяти, без localStorage: после перезагрузки страницы требуется повторный вход.
- При любом 401 защищённого API-запроса токен удаляется, навигация возвращается на вход.
  Ошибка 401 самого login отображается в форме и не запускает переход.
- При 429 кнопка блокируется по Retry-After в секундах; показываются оставшиеся минуты.
  Блокировка на сервере остаётся обязательной, даже после перезапуска приложения.
- Выход при зарегистрированном pushToken сначала DELETE /api/devices/:token,
  затем удаление JWT. FCM ещё не подключён, поэтому пока pushToken не регистрируется.
- Самостоятельная регистрация отсутствует в документированном API. Кнопка скрыта
  в серверном режиме; существующая форма остаётся только в демонстрационном режиме.

Наряды, справочники, уведомления и отчёты всё ещё используют DemoStore; в приложении
есть отметка «Демонстрационные данные». Настоящий профиль подставляется отдельно,
корпоративные моки не изменяются. Подключение входа не означает интеграцию нарядов.

MainApp(demoMode: true) оставляет прежний полностью локальный сценарий для тестов.
По умолчанию MainApp использует серверный вход. Для тестов AuthSession принимает
инъекции HTTP-клиента и TokenStorage.

Проверены формат запросов, JWT, 401, 429, короткие/длинные старые пароли, восстановление,
порядок отвязки push и удаления токена, выбор языка и переходы. Проверка с живой
учётной записью и на физическом телефоне ещё нужна: рабочие телефон/пароль не предоставлены.

Обновлённый контракт: GET /api/auth/me включает phone; login остаётся внутренним ID.
POST /api/auth/change-password отправляет currentPassword и newPassword. Экран
проверяет новый пароль 6–128 символов; 204 показывает успех и сохраняет JWT.
400 с неверным текущим паролем подсвечивает текущее поле и не завершает сессию.
ApiException хранит details: JSON-строку ошибок полей, массив либо простой текст.
Ошибки phone показываются у телефона; newPassword — у нового пароля.
Для login 400 без ошибки телефона подсвечивается пароль. SMS-восстановления нет.
